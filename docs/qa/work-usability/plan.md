# Work usability wave — binding plan

Branch `feature/agent-workboard`, base `ec8b27f`. Goal: make Work mode genuinely usable for an end user, reusing existing code wherever one exists. Six slices, one contract.

## Contract (binds every slice)

- **One desk write.** Every in-app entry point lands through `ConversationStore.upsertDeskMaterial` (headless callers `expectedOwnerRevision: nil`). Out-of-process or multi-file headless lanes write a `WorkCaptureEnvelope` and let `WorkCaptureDrainer` land it — they never publish a blob themselves. The one sanctioned direct headless writer of bytes is the voice lane (`WorkVoiceCaptureCoordinator`, as `ConverseIntent(destination: .work)` already uses it) because its recovery runs through `PendingRetryStore`, not the inbox. Storage mode comes only from `WorkMaterialStoragePolicy.mode(kind:byteSize:)`.
- **Voice: durable before the speech hop.** `WorkVoiceCaptureCoordinator.publishRecording` first, `attachTranscript` after. Neither a failed hop nor a missing transcript may lose the recording.
- **Nothing on the desk reaches a gateway.** No new surface may route a Work capture toward `startConverseHop`, a gateway ref, or a conversation.
- **Copy.** Every new user-facing string is a NEW catalog key with a `defaultValue:` literal at the call site. `workboard.*` copy never says send/dispatch/draft/brief. No App Intent title or description names a platform (UI copy may say iPhone where existing wrist copy already does). Reworded copy = new key. **Only the serial copy agent opens a `.xcstrings` file**; implementers list `key | defaultValue | comment` in their fixnote.
- **Mirror triplets** (`WorkCaptureEnvelope`, `ShareTargetsSnapshot`, `WorkCaptureDirectoryPublisher`) stay byte-identical from `import Foundation` onward. The envelope schema is NOT extended in this wave (audio is a MIME mapping in the drainer).
- **Relay wire strings** exist as literal duplicates in both `Wire` enums; edit both in one change and update `RelayWireSourceDriftGuardTests` + `RelayWireContractTests`.
- **Guard tests**: `WorkboardCopyTruthGuardTests`, `WorkboardDeskSurfaceDriftGuardTests` (exactly one `workboardViewModel.load()` in `PersonalWorkbenchView.swift`), `MacWorkbenchShellDriftGuardTests`, `WorkCaptureInboxTests` intent literal pins, `check-spec-size.sh` (spec at 16,649 of 16,900 words — pay for additions by trimming inside the same decision).
- **Tests**: new iOS test files auto-join `ConduckTests` (synchronized group); new WATCH test files need a pbxproj edit — put watch assertions in `ConduckWatchSmokeTests.swift`. Never `-configuration` on `xcodebuild test`/`build-for-testing`. Build caches under `~/Library/Caches/gigaduck-builds/<slug>` + `clean-build-cache.sh <slug>`.
- **Frozen**: `CaptureWorkboardIntent` (type, title, parameter keys, `parameterSummary`), App Shortcut phrases already shipped, reverse-DNS ids, serialized enum values.

## Slice A — desk cards and preview (macOS + iOS)

**A1 Thumbnails.** Generated at the ONE common import site: `ConversationStore.upsertDeskMaterial`, before the write context, when `draft.kind == .image && draft.thumbnailData == nil` — `ImageProcessor.thumbnailOnly(fromFileAt:)` for a `sourceFileURL`, `thumbnailOnly(from:)` for inline payload, on a `@concurrent` hop. This covers picker, drop, camera, the share/Shortcut drainer and chat capture with one edit; reattachment goes through `replaceWorkMaterialPayloadFile` (`:~1893`), which today clears `thumbnailData` (`:~2046`) — the same helper runs inside that replacement transaction. The store guard `storageMode == .syncedPayload ? draft.thumbnailData : nil` stays (vault bytes never sync). Backfill: `ConversationStore.repairMissingWorkThumbnails()` modelled on `setWorkMaterialCardSize` (presentation column on every duplicate row, NO `updatedAt`), bounded 96 rows / 4 concurrent decodes, called from `reconcileDurableWorkStorage()`; it re-validates each row's storage mode and content hash after decoding and marks permanently undecodable rows so it moves past them. Vault images keep the transient `localPresentationThumbnails` lane.

**A2 Image-forward cards.** In `WorkboardSourceCard.cardBody`: `kind == .image` with thumbnail bytes → `StagedImageTile` fills the tile (standard + large footprints) with name + footer over a bottom scrim; the availability glyph and the menu corner stay. Small footprint keeps artwork + one-line name (thumbnail as the artwork). Placeholder path stays reachable for thumbnail-less cards. Non-image layouts untouched; mosaic frames untouched.

**A3 Preview per kind.**
- Generalise `AttachmentFullScreenView` to a model-free `init(pages: [AttachmentGalleryPage], startIndex:, loadFullBytes:)` with a convenience init that keeps Chat's call site untouched; `ZoomableImagePage` unchanged.
- `PersonalWorkbenchRouter.present`: `kind == .image` (any lane, vault included) → `.imageGallery(pages:startIndex:)` built from every `.open`-permitted image card on the desk in board order, loader = `loadWorkMaterialPayload(id:)` **lazily per page**, full-resolution decode bounded to `maxPixel: 4096` through a STRICT bounded path that reports failure instead of falling back to unbounded platform decoding (`Image.decoded(from:maxPixel:)` at `Extensions.swift:~154` falls back to `UIImage(data:)`/`NSImage(data:)` when ImageIO fails — not acceptable for originals), and at most the current page ± 1 kept decoded (three 4096² RGBA bitmaps ≈ 192 MiB) — pages off screen release their bytes, neighbours released under memory pressure. `ZoomableImagePage` gains an explicit load/decode failure state with Retry (today it spins forever when neither image decodes). Rendered inside the existing `.sheet(item:)` (iOS honours one `.fullScreenCover` per view). Delete `WorkboardPreviewImage`; its `workboard.material.preview.unavailable.*` keys are reused by the failure state or removed by the copy agent (the bidirectional catalog guard catches orphans).
- `.file` → Quick Look: lift `FilePreviewCoordinator` out of `ConversationThreadView.swift` into `Views/Components/FilePreviewCoordinator.swift` and generalise its item from `AgentDownloadScratch.ScratchItem` to a small `PreviewedFile { url; reclaim: () -> Void }` (Chat's call site wraps its scratch item; behaviour unchanged). `PersonalWorkbenchView` gets its own instance + `.quickLookPreview(...)`, fed the disposable copy `makePreviewCopy` already produces. Lifetime keeps Chat's rule: iOS reclaims on dismiss; **macOS leaves the file for the launch age-sweep because Quick Look's Open With hands another app the live path** — so Work's preview-copy directory must be covered by that sweep (add its prefix/dir to the sweeper if it is not). Keep `ShareLink`. `.note`/`.link` sheets and the audio card stay.
- macOS sheet: extend `workboardDesktopSheetFrame` with ideal/max (`min 640×480, ideal 900×640`); main window default is 1100×760.
- Availability gate: `WorkboardOpenPathTests.testTheRouterRefusesACardWhoseBytesAreNotReadableHere` must still hold; gallery pages filter through `WorkboardCardActionPolicy`.

- `AppShortcuts`: two new entries, phrases without platform names ("Add files to Work in …", "Put this on my Work desk in …"; "Record a note to Work in …"). Existing three entries untouched.
- No Control widget (needs a new extension target). No desk read-back entity.

## Slice C — Watch

- **UI**: second bordered button "Save to Work" (`tray.and.arrow.down.fill`) on the launchpad between Ask and Conversations, reusing `refuseAskIfBusy()`; `WatchRoute.workCapture(nonce:)` → small `WatchWorkCaptureView` (recorder state + terminal line). Not a mode on Ask: a sticky mode's failure is a private thought going to a gateway.
- **Wire** (both `Wire` enums, byte-identical): `destinationKey = "destination"`, `destinationWork = "work"` (absent ⇒ chat), reply `resultWorkSavedKey = "result.work"` (Bool). Guards: `RelayWireSourceDriftGuardTests` 11 → 14, three new assertions in `RelayWireContractTests`.
- **Watch side**: `WatchCaptureDestination { chat, work }` as a separate field on `WatchRecordingService` (not a `WatchCaptureTarget` case); `startWorkCapture(requestID:)`; `.work` forces `needsiPhoneRelay`; `runRelay` stamps the wire and persists `destination` on the queue `Entry` (additive optional). **The reply is typed end to end**: `relay()` returns a `RelayReply { text; workSaved: Bool }` (not `String`), `RelayReplyOutcome.success` carries it, the wrist's live completion, late reconciliation and `drain()` all branch on `entry.destination` — a work entry NEVER calls `startDeferredConverseHop`/`startConverseHop`. `result.work == true` → terminal "Saved to Work". Reply WITHOUT the stamp (old phone build — transcript in hand, recording not kept) → write the words through the intent's `upsertDeskMaterial(WatchWorkboardCapture)` note-only path with a STABLE id derived from the requestID (UUIDv5, so a replay repairs rather than duplicates — the intent's default mints a fresh UUID), persist the note successfully BEFORE claiming the queue entry (`claimEntry` deletes the recording at `AppleRelayPendingQueue.swift:~202`) and before announcing, and say so ("Saved the words to Work. Update Conduck on your iPhone to keep recordings."). **Retention**: work entries are exempt from `maxEntryAge` AND from count eviction — a new Work capture is refused up front when the queue is at capacity ("Work is waiting for your iPhone. Bring it nearby first.") rather than evicting an earlier recording; the audio file is deleted only on a durable acknowledgement or an explicit discard. Retryability stays destination-specific (existing `WatchRelayQueueRetryabilityTests` terminal-error assertions unchanged for Chat). Deferred copy: "Saved on your watch. It reaches Work when your iPhone is nearby." Late completion posts a local notification "Saved to Work."
- **Phone side**: `destination` is threaded through BOTH ingress channels (`PhoneSessionManager` inline message ~L507 and `handleIncomingRelayFile`) into `processRelayRequest`; work branch reads the bytes before the defer deletes them, `publishRecording(captureID: UUID(requestID), …, sourceDevice: "watch")`, then the existing transcribe arms, then `attachTranscript` (handle `.recordingMissing`/`.notAudio` explicitly), reply `result.work = true` + `result.text`. `RelayReplyCache` gains an additive `workSaved` field so a cached replay carries the stamp. A phase-1 throw replies a RETRYABLE error code (never one the wrist's queue treats as terminal, e.g. `audioProcessingFailed`) so the wrist keeps its clip. `result.work` is only ever written on work replies — Chat's three-key success reply shape is pinned by `RelayWireContractTests`.
- Action Button / ControlWidget stay Chat-only. No Work browser on the wrist (it mounts no Blobs store).

## Slice E — CarPlay

- Picker row **"Add to Work"** (`tray.and.arrow.down.fill`) appended to `firstSectionItems` in BOTH the normal and the no-gateway branch; `cap` subtracts one more. No tab bar, no nav button.
- `startWorkNote(service:)` = `startSession` minus the gateway pre-flight; `CarPlayRecordingService.sessionDestination: .chat/.work`, `beginWorkNote()`, fifth voice state `saving` ("Saving…").
- `processRecording` forks after `AudioCompressor.compress`: `.work` → `publishRecording(captureID:…, sourceDevice: "carplay")` under the `saving` state, then the existing STT hop, then `attachTranscript` (handle `.recordingMissing`/`.notAudio` and throws explicitly) + `endSession(speak: "Saved to Work.")`. Every refusal below the fork and the empty-transcript case → `endSession(speak: "Saved to Work. Add the words on your iPhone.")` — never `handleEmptyTurn`'s re-arm. **Durability**: on the Work lane the compressed bytes are preserved through `PendingRetryStore` with destination `.work` BEFORE the original CAF is deleted, exactly as `ConverseIntent(destination: .work)` does (`publicationState` + the shared `recover(claim:)` lane); a phase-1 throw therefore leaves a retryable capture behind and speaks "Couldn't save that yet. Open Conduck to retry."; a successful publication marks the entry `.published` (NOT cleared) so recovery still covers the STT hop and the transcript attach, and the entry is disarmed only on a terminal outcome — the exact ordering of `ConverseIntent.swift:~355` (record publication state) and `:~656` (terminal gate). `isCurrentListen` is checked after EVERY suspension on the lane (compression, key readiness, publish, STT, attach).
- One-shot: no follow-up listen; `endSession(speak:)` releases the route after the spoken acknowledgement completes. Never lists Work cards on the car screen.
- Spec line 298 ("On CarPlay there is no such place") is rewritten. Entitlement category risk flagged for the founder (voice-based-conversation entitlement vs a memo action).

## Founder decisions taken by default (override at QA)

1. Watch: separate "Save to Work" button, not a mode on Ask.
2. Image gallery pages across every openable image card on the desk, lazily loaded, decode bounded to 4096 px, current ± 1 pages resident.
3. Non-image files open Quick Look (system share/open surfaces reachable).
4. Mac preview stays a sheet, not a window.
5. Thumbnail backfill: one bounded pass per reconcile.
6. Shortcuts: two actions (files, record) beside the frozen text action; >24 files refused outright; audio files become playable cards everywhere.
7. CarPlay: transcribe after publishing; row label "Add to Work"; row shown with no gateway configured; row-only entry (no note during a live chat session).
8. Mac: ⌃⌘W; text mode opens the compose surface in a Work-only state; popover holds the "Added to Work" banner (click opens the desk); no screenshot on the hotkey; no discovery tip.
9. `sourceDevice` is stamped ("watch"/"carplay") though nothing renders it yet.
10. Watch: no note-only fallback on eviction (there is no eviction of Work entries; capacity refuses up front). The note-only fallback exists only for an old phone build that returns a transcript without the Work stamp.
11. CarPlay phase-1 failure preserves the recording for retry through the same pending-retry lane the headless Shortcut uses.
