## What this wave is

Work was a desk you could put things on and not much else. It is now a desk you can *use*: a picture card is the picture, a tap opens the right viewer for the kind of thing tapped, and every surface Conduck already owns has a door onto it — the share sheet, two Shortcuts actions, the Mac menu bar's own hotkey, the wrist, and a CarPlay row. Nothing on any of those lanes reaches a gateway, and no capture surface writes a card its own way: they all land through the one desk write, or hand an envelope to the drainer that does. On every satellite surface — the share sheet included — Work is a DESTINATION the person names: the last row of the wrist's Ask chooser, a root row in the car's picker, the Mac's third capture hotkey, the last row of the share sheet's one destination list. Naming it buys one speech hop where there is speech at all, and nothing else.

## What shipped

**Thumbnails.** A preview is minted at the one common import site — `ConversationStore.upsertDeskMaterial`, before the write context — and again inside the transaction that replaces a payload, so picker, drop, camera, share sheet, Shortcut drainer and chat capture are all covered by one edit. The decode runs on a `@concurrent` hop, never on the store actor, and the lane gate reads the *staged* storage mode rather than the draft's claim, so vault bytes never buy a preview that CloudKit would carry. `repairMissingWorkThumbnails()` fills rows that carry none, bounded to 96 rows and 4 concurrent decodes per pass, writing every physical row and no `updatedAt` — a revision moved by a preview nobody asked for reads as an edit and invalidates an approved preflight.

**Image-forward cards.** A `.image` card with thumbnail bytes fills its tile at the standard and large footprints: the photo edge to edge, name and footer on a bottom gradient that grows with Dynamic Type, the availability glyph on a dark disc so its tint survives an arbitrary picture. Small keeps the old artwork-plus-name row. The two layouts are two separate view chains, so the glyph card's geometry cannot be moved by the photo card's existence, and the menu corner is drawn outside both.

**Preview per kind.** `AttachmentFullScreenView` is model-free: it takes pages, a start index and a byte loader, and Chat's call site keeps its old convenience init untouched. Tapping any image card — vault lane included — opens a desk-wide gallery of every `.open`-permitted picture in board order, loaded lazily per page, decoded through a strictly bounded ImageIO path at 4096 px with no unbounded platform fallback, and holding at most the current page ± 1; a memory warning drops the radius to zero for the life of the presentation. A load or decode failure shows a message and a Retry rather than spinning forever. Files and recordings go to Quick Look through `FilePreviewCoordinator`, lifted out of `ConversationThreadView` into `Views/Components/` and generalised to a `PreviewedFile { url; reclaim }` so each lane keeps ownership of the unit it created; iOS reclaims on dismissal, macOS leaves the copy to the launch age-sweep because Quick Look's Open With hands another app the live path.

**Shortcuts.** `AddFilesToWorkIntent` copies every source into its own scratch leaf first, taking the copy and its SHA-256 in one streamed pass, and the capture identity is derived from those snapshots — the bytes it goes on to publish — never from the source it read, because a source rewritten between the two reads would otherwise repoint an earlier capture's cards onto different bytes. A digest, read or write failure refuses the whole capture rather than naming an empty one. It then publishes one envelope through `WorkCaptureInbox.publishFileCapture`, which copies bytes rather than reading them (a headless process must not hold 256 MB) and checks per-file and envelope ceilings twice — once against the declared sizes before a byte is copied and once against the staged snapshots — and derives each entry id as a UUIDv5 over the capture id and sequence, so a killed-and-rerun Shortcut repairs its own cards instead of laying a second set. Staging costs peak scratch: a URL-backed set is resident twice, once as the snapshot and once as the queue's copy. `RecordWorkNoteIntent` only launches the in-app recorder, through a consumable pending route that survives a cold launch. The drainer maps an audio `.file` entry to a playable `.audio` card, which the share sheet gets too.

**Watch.** Ask opens a destination chooser titled **Where to?** on every press — every configured gateway in roster order, then **Add to Work** as the last row, with "No personal AI available." above it when the roster is empty — and the Work row pushes its own route rather than a mode on Ask, because a sticky mode's failure is a private thought going to a gateway. A pick is per press, so nothing stays switched on; the picked destination is named on the recording overlay while the mic arms and runs, and two gateways whose names shorten alike are told apart on the wrist's own labels with the full name spoken to VoiceOver. A Work capture always relays, whatever the speech provider, and the reply is typed end to end (`RelayReply { text; workSaved }`), so a work entry can never take a converse hop. The phone reads the bytes before the defer deletes them, publishes with `sourceDevice: "watch"`, then transcribes and attaches; a phase-one throw replies a retryable code so the wrist keeps its clip. Work entries are exempt from both age and count eviction — a capture at capacity is refused up front rather than an older recording being deleted — and the clip goes only on a durable acknowledgement or an explicit discard. A settled failure *after* publication — the desk holds the recording, the words are unrecoverable — replies success-shaped with the stamp and an empty transcript, so the wrist releases its clip and ends on "Saved to Work. Add the words on your iPhone." on both the live and the deferred leg; only a retryable verdict travels back as an error, because the entry that keeps its clip is the one that can still win the words on a re-fire. A phone too old to send the stamp returns words alone, which land as a note under an id derived from the request (so a re-fire repairs rather than duplicates), written and confirmed before the queue entry is claimed.

**Mac menu bar.** `⌃⌘W` captures straight to the desk: it raises the drag-select overlay first (a picture is optional — Return skips it, Esc abandons the press), then the popover opens on the shared capture HUD pinned `.applicationDefined` from the moment the start is in flight, not from the moment the mic is live, so a click-away during startup cannot leave a microphone coming up behind a closed popover; the voice press claims the popover *before* it shows it, so summoning Work never marks an unread Chat reply as seen. The acknowledgement is a button that opens the desk with the card already on it (the capture drains inline), and each lane owns its own receipt — voice says "Added to Work. The words came from your speech provider.", the typed quick note says "Added to Work. Nothing was sent.", because only the typed lane can promise that nothing left the device. A voice request that arrives at a fully quit Mac is honoured by the launch lifecycle itself: the app activates and reveals Work rather than waiting for a window that would otherwise never exist. In text mode the same key opens the compose surface in a Work-only state — no Ask affordance, header "Add to Work" — whose composition is stored with its aim, so a dismissed Work draft is never offered to Chat's Return on the next `⌘⇧1`. A "Capture to Work…" context-menu item — the last of the three capture commands, with a separator between it and the two "Open" rows, of which "Open Work" carries no ellipsis because it asks for nothing — and a "Capture to Work" recorder row in Settings → General are the other two doors; a click on the status item stops a live Work recording, and an Ask press while the Work mic is live shows the running capture instead of pushing dictation into a stale error. Whichever lane holds the MICROPHONE owns the surface: a Work capture stays active through its transcription and through a standing error, so the popover router, the status glyph, the click and the bail all yield to a live Ask recording and all return to Work at its stop — four rules that must agree, or a click stops what the surface hides and a ✕ discards what it cannot show. `⌃⌘W` asks `SpeechExclusivity` BEFORE it raises the crosshair and stands down with the existing busy sentence rather than letting somebody drag a region the post-await guard then drops; a secondary click is the context menu in every state, including mid-recording, where it used to stop and send; and "Start Recording" in that menu is `handleShortcutPress()` itself, since a menu door with an arm of its own re-arms a turn already in flight. The typed receipt binds the inline drain: a drain that returned says "Added to Work. Nothing was sent." over a button that opens the desk, one that threw says "On its way to Work. Nothing was sent." as an inert row, and the desk is re-read for this capture's card rather than trusting the report, which identifies nobody.

**CarPlay.** A permanent "Add to Work" row in both picker states records one note and never browses. `processRecording` forks after compression: the compressed bytes are written and armed in `PendingRetryStore` with destination `.work` *before* the original CAF is deleted, so every refusal below that point costs the words and never the recording; publication marks the entry `.published` rather than clearing it, so recovery still covers the speech hop and the attach. Empty transcripts and refusals below the fork speak "Saved to Work. Add the words on your iPhone." and never re-arm; `isCurrentListen` is re-checked after every suspension on the lane. The attach asks `PendingRetryGuard.stillOwnsCapture` first and writes nothing if it has lost the capture: `attachTranscript` is idempotent only for identical words, so a lane that no longer owns a capture would silently overwrite a retry's transcript with older ones. A startup failure below `.recording` — audio session, capture file, VAD, exhausted engine retries — ends through one terminal that ends the session and then drives the scene itself, dismissing the modal and refreshing the picker onto the "Mic couldn't start" hint, because `state` never leaves `.idle` on that path and an equal assignment publishes no observation. One start is claimed at a time: `claimStart` takes a serial synchronously at the row tap, `startIsLive` re-asks after every suspension and inside both present completions, and only the holder releases it, so a chat start suspended in its gateway pre-flight can never begin under an Add-to-Work tap and a completion from a previous connection mutates nothing. A Work note carries End and no Mute — Mute tears capture down and deletes the partial recording, which is call-style behaviour on a multi-turn chat and silent loss on a one-shot note — and never re-arms after a settle. The "Mic couldn't start" hint names the row that failed, because "Tap New voice chat to try again." would route the repeated private thought to an AI; with no gateway configured the picker lists **Add to Work** above "Set up your AI on iPhone first.", so the row that works is not read as needing the setup above it. The words are parked on the queue entry before the attach, so a throw or a lost claim leaves them beside the bytes, and a published Work entry keeps them retryable for a day rather than ten minutes — the car is the surface where nobody can act inside ten minutes, and "Add the words on your iPhone" has to still be true when the drive ends.

**Share.** Every card shares — note as text, link as URL, image, file and recording as a disposable copy of the original bytes — from its context menu and its VoiceOver actions, and the gallery shares the page in view. `WorkMaterialShareCoordinator` (owned by the router beside Quick Look's coordinator) gates on the STORE's current material, not the board's debounced copy: store gate → bind name and type to that revision → prepare off the actor behind a Preparing banner drawn by the shell and the gallery alike → wait for the menu's dismissal to settle → store gate again → present, with the request token re-checked after every await. iOS presents `UIActivityViewController` anchored by `sourceView`/`sourceRect` (the iPad trap); macOS shows a retained `NSSharingServicePicker` against the surface's view and drops the retain on choose/dismiss. `SharePresentationAnchor` is a newest-ATTACHED-wins registry, reordered only in `viewDidMoveToWindow`, so a share from the gallery pops out of the gallery. `WorkMaterialExportSnapshot` is the one disposable-copy path for Quick Look and Share: a recognised extension in the title wins, then the stored MIME type, then the vault leaf (`Meeting v1.2` no longer becomes `.2`); each copy sits in its own `Conduck-Workboard-Preview-<UUID>/` leaf so the sweep ages copies one by one. A copy that failed or was refused presentation is reclaimed at once; a copy handed to the share UI is retained for the sweep. Keys `workboard.material.share` and `workboard.material.share.*` only; `common.share` stays retired. Store-side, a refused reattach's rollback now moves every row's revision (per row, effective revision + 1 ms) so a bytes swap can never hide behind a restored stamp, and the single-row canonical read `workMaterialRow` and the board's dedupe both reduce to `max` over one total ordering, `WorkMaterialCanonicalOrder` (effective revision, createdAt, title, contentHash, row key) — before, an undated duplicate the board showed could never be the row the payload reader served, and a full tie was fetch-order dependent.

**Capture to Work.** `⌃⌘W` opens with the same drag-select overlay `⌘⇧2` uses, because a note about what is on screen is the thing people reach for. `RegionCaptureController` answers a four-case `RegionCaptureOutcome` instead of `Data?` — `.captured`, `.skipped`, `.cancelled`, `.unavailable` — since one `nil` cannot separate "chose no picture" from "could not take one", and guessing either way either starts a microphone nobody asked for or drops the note somebody did ask for. A `RegionCapturePurpose` drives the hint (`Drag to capture · Return to skip · Esc to cancel`), whether Return skips, a "Skip screenshot" accessibility action, and the alert copy: Ask's wording promises the picture and the words go to the configured gateway, which is false on a lane whose desk reaches none, so Work has its own bodies and every Work Screen Recording permission stop offers "Continue Without Screenshot" with Cancel last (the microphone alert offers none — a missing mic stops the recording, not the picture). A sub-4pt drag stays a cancel on both lanes — a stray click must never read as "record without a picture". The status-item menu names the action "Capture to Work…" (new key; `menu.recordToWork` retired), a `.separator()` closes the capture group, and "Open Work" drops its ellipsis under a new key because it asks for nothing first. The three capture surfaces now draw ONE HUD, `captureHUD`: staged thumbnail if any, one indicator, one compact ✕ — no headline, no "Stop and Save" capsule, no privacy paragraph, because stopping is hotkey-first and a boundary is stated once rather than on every capture. A left-click on the status item stops a live Work recording, which is the only stop left for somebody who cleared the binding; clicks during startup or transcription raise the running capture and start nothing. The press order is screenshot → validate → claim → show → cue → record, and `MenuBarCoordinator.workCaptureCancellationGeneration` is reserved before the overlay and compared after it, because for the whole length of that await the lane owns nothing an Esc could change — without it a bail lands, does nothing observable, and is answered seconds later by a microphone coming up behind the popover it just closed. `workCapturePressInFlight` drops a second press while the crosshair stands. The Esc monitor consumes Esc only for the popover's own window, so the overlay keeps the key it exists to listen for; closing the popover ahead of the overlay was rejected because a popover can hold a parked Work composition. The picture rides a Work-ONLY slot (`pendingWorkCaptureImage`): `pendingCaptureImage` becomes a `PendingAttachment.image` on the next chat turn, and a screenshot of somebody's screen leaking into an Ask made minutes later is the sharper version of the leak the two-composition design exists to prevent. `saveQuickDraftToWork` publishes the picture the AIM owns, so the Chat door's "Add to Work" still files what `⌘⇧2` staged. In the voice lane the bytes are STAGED until Stop — one Esc still leaves the desk untouched — then published FIRST, ahead of the recording, through `WorkVoiceScreenshotCoordinator` under the capture's own `createdAt`, so the one artifact a crash can destroy is the one held only in memory. The two artifacts answer independently: a refused picture costs neither the recording nor the words, but it holds the capture retryable, and one Try Again finishes it in a single pass with no speech hop (phase one skipped, transcription skipped, and phase two skipped outright because `transcriptSettled` records the words as already settled). A published recording immediately rewrites the `.phaseOneFailed` verdict a refused picture armed, `discardWorkImage` retires the parked copy the moment the durable inbox ACCEPTS the envelope, not when a card owns it, and `holdsWorkImage` exempts an entry still sheltering an unpublished picture from the expiry clock. The HUD's error sentence is composed from `InAppAudioRecorder.workCaptureFacts` (recordingOnDesk / wordsOnDesk / screenshotStaged / screenshotOnDesk), never inferred from the error, because any of the three artifacts can land while the next is refused; the receipt band renders only a whole success, and a capture that skipped its screenshot is never told one is missing.

## Founder decisions taken by default (override at QA)

From the plan:

1. Watch: **Add to Work** is the last row of the Ask destination chooser, which opens on every Ask press — 0, 1 or N gateways. No separate launchpad button, and no mode on Ask: the pick is per press, so there is no last destination to leave switched on.
2. Image gallery pages across every openable image card on the desk, lazily loaded, decode bounded to 4096 px, current ± 1 pages resident.
3. Non-image files open Quick Look (system share and Open With reachable).
4. Mac preview stays a sheet, not a window.
5. Thumbnail backfill: one bounded pass per reconcile.
6. Shortcuts: two actions beside the frozen text action; more than 24 files refused outright; audio files become playable cards everywhere.
7. CarPlay: transcribe after publishing; row label **"Add to Work"** on BOTH of its doors. The permanent ROOT row is shown whatever the roster holds and listed FIRST where no gateway is — day one's only working row, and the fewest taps everywhere else. Where the nav-bar "Choose AI" list exists at all (two or more gateways, or the repair chooser a broken default pushes), that list ends with the same **Add to Work** row, after every gateway row: Codex's both-doors shape, specified in `design/carplay-work-destination.md` §9 and taken by founder decision. It is an ACTION, never a pick — no checkmark, no session-local override, no destination stored anywhere — so the tap starts the note and is over, and the next "New voice chat" resolves its gateway from exactly the state it would have had if the row had never been tapped. It claims the single in-flight start BEFORE it pops (the row underneath the chooser is "New voice chat") and hands that same serial to the shared presentation, so the one-start rule and the g1 audio-race contract are the root row's, unchanged. A single-gateway phone grows no switcher and therefore no second door. The chooser keeps its "Choose AI" title (`chat.chooseAI.label`); renaming it to a destination title needs a new key and is a founder call (U-64). A Work note offers End and no Mute. Row-only entry, no note during a live chat session.
8. Mac: ⌃⌘W; the press opens the drag-select overlay first, so a screenshot is optional decoration on the note — Return skips it, Esc abandons the whole press — and only then does it record or open the compose surface Work-only; the popover holds the "Added to Work" banner; no discovery tip.
9. `sourceDevice` is stamped ("watch" / "carplay") though nothing renders it yet.
10. Watch: no note-only fallback on eviction, because Work entries are never evicted. The note-only path exists solely for an old phone build that returns a transcript without the Work stamp.
11. CarPlay phase-one failure preserves the recording for retry through the same pending-retry lane the headless Shortcut uses.

Raised by the fixnotes and taken the same way:

12. **Share is on every card and in the gallery**, not images only and not context-menu only: one "Share" everywhere is more discoverable than "images share here, files share inside Quick Look", and a person who has just inspected a picture should not have to close it to send it. Shared bytes are always the original, never the display image.
13. **Resolved: whichever lane holds the microphone owns the surface.** A Work capture parked in transcription or in a retryable error keeps `workCaptureIsActive == true`, and now yields the popover, the status glyph, the status-item click and the ✕/Esc bail to a live Ask recording, taking all four back at its stop with its Try Again intact — a running microphone with no visible surface is the failure the rule exists to prevent, and the click rule already said so. Reverse it at QA if you would rather the Work error stay on top and accept a hidden live microphone.
14. **CarPlay's entitlement category is unsettled.** The official target declares `com.apple.developer.carplay-voice-based-conversation` (`Conduck/Conduck/Conduck-Official.entitlements`); a memo that reaches no other person is arguably outside that category. Mitigation is already in the build — the row draws no desk content, so removing it is a one-row change. Recommendation: raise it in the review notes rather than wait to be asked.
15. **⌃⌘W is assumed unbound.** Verifiable only on the founder's own Mac, against System Settings *and* any launcher (Raycast, Alfred). If it is taken, the hotkey silently does nothing; remap it in Settings → General → Keyboard Shortcut.
16. **`width` / `height` stay nil on captured images.** `ImageProcessor.thumbnailOnly` returns bytes only, and filling the columns would mean a second ImageIO read owned by the store. Nothing reads those fields today; the full-bleed tile crops to the slot, which is what image-forward wants anyway.
17. **A recovered capture stamps the recovering device.** `republishRecording` re-publishes parked bytes with the default `sourceDevice`, because `PendingRetryStore` metadata carries no such field — so a wrist or car capture whose phase one failed and is finished later on the phone reads as the phone. Costs nothing while decision 9 holds.
18. **Watch: the picked destination is named on the recording screen** through arming and recording, and two gateways whose short names collide are told apart on the wrist's own labels with the full name spoken to VoiceOver. A per-press pick rules out a stale mode but not an honest mis-tap, and a mis-tap you cannot see is one you cannot cancel.
19. **A published Work retry entry keeps its words for a day**, not the ten minutes a Chat transcription gets (`PendingRetryStore.publishedWorkRetryTTL`). The car is the surface where nobody can act inside ten minutes, so "Add the words on your iPhone" has to survive the drive; the clock still governs, because those bytes are a SECOND copy of a recording already on the desk. Shared-service change — the Mac and phone lanes inherit it. An UNPUBLISHED Work entry is still exempt from every clock.
20. **The Mac typed receipt only claims a card the desk holds.** The inline drain must return AND this capture's card must read back before "Added to Work. Nothing was sent." is said over a door; a drain that threw says "On its way to Work. Nothing was sent." as an inert row, because the envelope is durable but nothing has imported it yet.
21. **Share sheet (iOS + Mac): Add to Work is the last row of the ONE destination list**, under its own "Work" header, after every gateway and every recent chat — and **nothing is pre-selected**. The primary button reads "Choose a destination" and is disabled until a row is tapped, then "Add to Work" or "Send now"; ⌘-Return fires only an enabled button. The Work / Send now segment and the Work explanation panel are gone, the iOS title is the wrist's "Where to?", a decoded roster with no gateway and no recent shows "No personal AI available." above the Work row, and no snapshot at all keeps the legacy "New conversation" row — now tappable, because nothing is picked for the person. Nothing is remembered between shares. Cost, stated plainly: share-and-go is two taps where it was one. Reverse it at QA by pre-selecting the first gateway — which re-opens the direction the boundary calls unrecoverable, so it is a founder call.

## Founder QA script

Ordered, grouped by surface, and the first step is the irreversible one. Failure cases are named; "must be true" is the assertion. Where a step says *known behaviour*, it is a decision above, not a bug — report it only if you dislike it.

## Standing constraints (any future agent)

Build caches under `~/Library/Caches/gigaduck-builds/<slug>` plus `clean-build-cache.sh <slug>`, and **clean only your own slug** — a `work-*` glob wipe turned another agent's in-flight `xcodebuild` into a phantom failure twice in this wave · **never `rm` anything in an agent session**; move unwanted files into the session scratchpad instead · never `-configuration` on `xcodebuild test` / `build-for-testing` · **never RUN the macOS test bundle** — `WorkboardAudioCaptureTests` hangs on the macOS test host and takes the whole gate with it; `build-for-testing` is the macOS gate, and the same sources are RUN by the iOS suite · **prefix every path with the absolute worktree root**: a shell's cwd drifts between calls, so a relative `grep`, `sed` or bare `git -C` resolves into the monorepo's own `Conduck/` submodule checkout on `main` and reports this branch's work as missing — a trap that reads as "the change was never made" · check the simulator's TCC row before trusting a red audio run · never touch the `Conduck/Configs/Identity-Override.xcconfig` symlink · mirror triplets change byte-identically or not at all · parallel agents never edit `.xcstrings` — one serial copy agent owns both catalogs · **one owner per shared contract type**: where two targets hold literal duplicates of a wire enum, one agent edits both copies in one change and updates the drift guards with them, and no agent writes a temporary stub of another agent's type · docs are present-tense end state, no changelog narration · the "Nobody undo" lists in every fixnote interlock — read the relevant one before changing a mechanism · never rebase this branch; merge only · never push unasked.
