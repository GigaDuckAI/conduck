# CarPlay Work destination — design

Lane: CarPlay. Tip under review: `a197ccd`. Author: designer agent (reads code and docs, writes this file and the Codex reports only). Codex rounds: `verify/codex-design-carplay-r1.md`, `r2.md`, `r3.md`; §10 records what was accepted, refused and left open.

**Verdict: `change_required`.** The founder's *intent* — Work is a destination the driver can pick in the car, a pick means speech-to-text only, no LLM step, no gateway — is what ships at the tip, and the shape (a one-tap root row; the "Choose AI" chooser stays AI-only) is kept for the reasons in §3. The review surfaced one boundary bug that must be fixed before the lane is accepted (P1: a start race can turn a tapped Work note into an AI chat), and four P2 items: a Work note's Mute button silently discards what was already said; the mic-failure hint sends a failed Work start to the AI row; the words are parked nowhere when the attach fails; and a published Work capture's retry entry expires ten minutes after a capture the driver cannot act on for the length of the drive. §9 specifies the founder's stated shape as a non-sticky action row, so an override at QA is one decision.

---

## 1. What the lane does today

**Entry points.** The permanent root is a `CPListTemplate` picker (`CarPlaySceneDelegate.refreshPicker`). First section, in order: the one-shot "Mic couldn't start" hint (only after a silent start failure), **"New voice chat"** (`mic.fill`), **"Add to Work"** (`tray.and.arrow.down.fill`, `makeWorkNoteItem`); then a "Recent" section of conversations (label + relative date, never text). With **no gateway configured** the first section is: hint → "Set up your AI on iPhone first." → **"Add to Work"**, and no Recent. So Work is one tap from the root in both states, on day one included.

**The gateway chooser** is a *different* control: a leading nav-bar `CPBarButton` titled with the effective gateway's short name, shown only when ≥2 gateways are configured, pushing a "Choose AI" `CPListTemplate` (`presentGatewayChooser`). Picking a row sets `sessionDefaultRefOverride: RemoteAgentRef?` — a drive-long, session-local override that re-aims **"New voice chat" only** (recents stay bound to their own `Conversation.backend`), never writes the phone's default, and dies on `didDisconnect`/`teardown`. `newChatPlan` (pure, tested in `HeadlessGatewayPreflightTests`) also *pushes this chooser itself* as the repair step when the phone's default is unavailable or unchosen ("Your default AI, X, isn't available. Choose another from the list.").

**Work lane, end to end** (`startWorkNote` → `CarPlayRecordingService.beginWorkNote` → `startListening` → `processRecording` with `sessionDestination == .work`). The guarantees, stated exactly:

| Step | What happens | Guarantee |
|---|---|---|
| Tap "Add to Work" | `startWorkNote`: no pre-flight, no snapshot, no ref; voice modal presented, `beginWorkNote()` inside the present completion (g1) | nothing recorded yet |
| Listen | one listen; VAD end-of-speech; initial silence ≈15 s signs off; End discards the partial CAF; **Mute tears down capture and deletes the partial CAF; Unmute starts a fresh listen** (`mute()`/`unmute()`, `CarPlayRecordingService.swift:~650–690`) | End/Mute while listening: nothing durable |
| Fork after `AudioCompressor.compress` | `secureWorkNote`: compressed copy written; `PendingRetryGuard.arm(destination: .work)` — **its `Token.audioPreserved` is false when the App-Group save failed**; the container CAF is deleted right after `arm` returns regardless; `saving` template state; `WorkVoiceCaptureCoordinator.publishRecording(sourceDevice: "carplay")`; entry marked `.published` (not cleared) | a non-nil `WorkNoteCapture` proves the **desk write** succeeded; the queue's second copy exists only when `audioPreserved` |
| Publish throws | entry `.phaseOneFailed`; spoken "Couldn't save that yet. Open Conduck to retry." when `audioPreserved`, else "Couldn't save — try again." | nothing durable when both writes failed, and the line says so |
| Speech hop | existing STT client; custom-endpoint (refused on CarPlay every time, by design), missing/unreadable key, network, and empty transcript all end on "Saved to Work. Add the words on your iPhone."; entry left armed | words retryable from the phone **while the entry lives** (see P2-D) |
| Attach | `attachWorkNoteTranscript`: `PendingRetryGuard.stillOwnsCapture` first, `isCurrentListen` after every suspension, `attachTranscript`; `.attached` → disarm + "Saved to Work."; `.recordingMissing`/`.notAudio`/throw → left armed + saved-without-words line; **the transcript is not parked on the entry** | words on the same card, or a retry that re-buys them |
| End | `endSession(speak:)` one-shot: no follow-up listen, route released in the dismiss completion, `sessionDestination` reset to `.chat` in `endSession` AND `teardown`; the container CAF removed on every terminal path | — |

`CarPlayEmptyTurnPolicy` (retry-once-then-end) is chat-only: an empty transcript on the Work lane ends on the saved-without-words line and never re-arms. No Work card is ever drawn on the car screen.

**Tests that pin it** (`CarPlayWorkNoteTests`, 22 cases): row budget arithmetic; `sessionDestination` default/reset; `beginWorkNote` touches nothing a gateway would need; acknowledgement matrix; secure-before-STT ordering; `.published` not cleared; ownership gate before attach; scratch-file `defer`s; staleness after every suspension; no gateway / no re-arm on the lane; `startWorkNote` forbids `newChatPlan`/`effectiveCarPlayRef`/`sessionDefaultRefOverride`; `makeWorkNoteItem(` appears exactly twice in `refreshPicker`; the no-gateway hint uses `.detail.work`; the silent-start terminal. Plus `HeadlessGatewayPreflightTests` (`newChatPlan`, `sessionOverrideRef`), `CarPlayVoiceTimingContractTests` (hint keys in the catalog), `PendingRetryQueueTests` (expiry rule), `WorkVoiceRecoveryTests`, `STTKeyBlackoutLaneTests` and `HeadlessRefusalLaneDriftGuardTests` (both scan these two files' source).

## 2. The founder's words, judged against the code

> "Then in carplay we have the gateway selector. we add work as a destination and then its just STT, no LLM step."

| Clause | Ships? | Where |
|---|---|---|
| Work is a destination the driver picks in the car | **Yes** | root picker row, both states |
| picking it means STT only | **Yes** | `processRecording` Work fork: publish → STT → attach |
| no LLM step | **Yes** | `beginWorkNote` never registers with `CarPlayConverseUploader`; `startConverseHop` unreachable on the lane (`testTheWorkLaneReachesNoGatewayAndNeverReArmsTheMicrophone`) |
| "in the gateway selector" | **Not literally** — the Work door is a root row; the "Choose AI" list stays AI-only | §3 decisions 1–4; §9 is the literal shape, for an override |

What the founder describes is a **destination picker** with gateways and Work side by side. On CarPlay the root list already *is* that picker: "New voice chat" is the AI, "Add to Work" is the desk, one tap each. The nav-bar "Choose AI" list is a narrower thing — *which* AI, for this drive, remembered until the cable drops — and a Work entry there is either a mode (unsafe, decision 2) or a second door to a row that is already one tap away (decision 1).

## 3. Decisions

| # | Decision | Why |
|---|---|---|
| 1 | **Work stays a one-tap root row; no Work row in "Choose AI".** | A thought at the wheel costs one tap today. Any chooser placement costs at least two (switcher → Work) through a pushed template, and — because the row must stay for day one and for one-tap reach — a chooser Work row is a *second* door to the same action: more buttons, a nav-bar switcher that would have to appear with a single gateway solely to reach it, and a "Choose AI" list mixing checkmark rows that set drive-long state with an action row that starts a recording. Codex's round-1 counter-proposal (both doors, chooser at ≥1 gateway) was weighed and refused on exactly that count: two taps and two doors for nothing the one tap does not already give. |
| 2 | **No drive-long Work mode — the override names a gateway and never the desk.** | The chooser is *sticky*: its override lives until the cable drops and resets silently on every reconnect (fuel stop, cable bump, host restart). Between two gateways a stale override costs "wrong AI"; between an AI and the desk it changes category, so a driver who *believes* Work is selected taps row 0 and a private thought goes to an AI. That is the failure the wrist's "not a mode on Ask" decision (handoff decision 1) exists to prevent, and the invariant this wave guards. `CarPlayCaptureDestination`'s own doc comment states it: "a sticky mode's failure is a private thought reaching a gateway." Codex agrees. |
| 3 | **The chooser stays at ≥2 gateways.** | With Work not in it, a switcher titled with the only gateway is a dead button. |
| 4 | **The chooser stays the AI-repair surface, AI-only; `newChatPlan`, `effectiveCarPlayRef`, `sessionDefaultRefOverride` stay `RemoteAgentRef`-typed.** | `newChatPlan` speaks "Choose another from the list" and pushes this list when the default is broken; "Work" there is a non-answer to "which AI?". Keeping the types gateway-only is what keeps Work out of the gateway pre-flight (`testTheWorkRowStartsASessionWithNoGatewayPreFlight…`). |
| 5 | **Day one: the working row first.** No-gateway first section becomes hint → **"Add to Work"** → "Set up your AI on iPhone first." | Today the setup hint sits above the only row that works, and reads as its prerequisite. Reordering is one line (P2-C below). |
| 6 | **Names: destination "Work", action "Add to Work", success "Saved to Work."** | "Add to Work" is the action label on iOS (Shortcut, menu-bar compose header, desk composer, chat capture); the two saved lines are byte-identical to the wrist's `watch.work.capture.saved` / `.savedWithoutWords`; "Saved" states the fact that matters at the wheel. Different verbs are not different names for the destination. |
| 7 | **A Work note has no Mute button.** | `mute()` while listening tears down capture and *deletes the partial recording*; Unmute starts a fresh listen. On a multi-turn chat that is call-style mute and the spec keeps it. On a one-shot note it silently throws away everything said before the tap and keeps the route held with no timer. Making Mute preserve would mean pause/append in the recorder; removing the button is one line and one fewer control — End remains. (P2-A) |
| 8 | **One session start at a time, claimed synchronously and bound to the connection.** | `startSession` guards `.idle && !sessionActive`, then suspends on the gateway pre-flight; `startWorkNote` can pass the same guard during that suspension and present the modal; `ensureVoicePresented` sets `isVoicePresented` *before* the present completes and runs any later caller's completion immediately — so the resumed chat start calls `beginSession` before Work's `beginWorkNote`, wins the guard, and the driver who tapped Add to Work is in a chat session (and g1 is broken for it). A boundary breach the driver only discovers when an AI answers a private note. The claim carries a serial and is re-validated against the live service after every suspension, so a start left over from a previous connection can neither begin nor release the new connection's claim. (P1) |
| 9 | **The mic-failure hint names the row that failed.** | After a failed Work start the configured picker says "Tap New voice chat to try again." — an instruction that routes the repeated private thought to an AI, and fails QA step 73 as written. (P2-B) |
| 10 | **Words are parked on the queue entry before the attach.** | `attachTranscript` can throw or lose ownership after recognition succeeded; today the transcript then exists only in the car's process and the phone re-buys it. `PendingRetryGuard.recordPublicationState(token, transcript:, publicationState: .published)` already exists and `ContentView`'s retry already finishes a parked Work transcript with no speech hop. Parking *before* the attach (rather than in the catch, as `ConverseIntent` does) also covers a kill during the attach; the ownership question is asked *after* the parking, because the parking is a suspension and `recordPublicationState` answers false both for an overtaken claim and for an arm that preserved nothing. (P2-E) |
| 11 | **A published Work capture's retry entry keeps its words retryable for 24 hours.** | `PendingRetryMetadata.isExemptFromExpiry` is `work && publicationState != .published`, so a *published* Work capture whose words failed is swept `transcriptionRetryTTL` = 600 s after `createdAt`. The car is the surface where the person cannot act inside ten minutes; "Add the words on your iPhone" is then false after any real drive, and nothing on the desk can transcribe an audio card later. The rule was deliberate (a Chat transcription "can be bought again"; the desk holds the recording), but the *words* cannot be bought again without the entry. Settled by the orchestrator: the clock still governs, but a `.published` Work entry gets its own 24 h budget (`86_400` s, named constant beside `transcriptionRetryTTL`) instead of the 600 s one, so a drive and a locked phone are covered while retention stays bounded and the menu-bar lane's invariant (a published recording's queue copy is not irreplaceable) stays true. `holdsWorkImage` untouched. Shared-service change, owner = integrator; exit is the existing confirmed discard (`pendingRetry.card.discard.confirm.body.published`) or the 24 h clock. (P2-D) |
| 12 | **Voice template lifecycle unchanged.** | Modal-only voice template over the permanent root; `beginWorkNote` inside the present completion (g1); `saving` is a template state with no `State` case; silent start failure drives the scene through `applyState` (fix-r2 R1). |
| 13 | **Refusal behaviour stays as shipped.** | Recording armed before the CAF is deleted; ownership check before the attach; empty transcript = saved-without-words, never `CarPlayEmptyTurnPolicy`'s re-arm; `.recordingMissing`/`.notAudio` leave the entry armed and speak the saved-without-words line (the card was published this session; an id naming no card afterwards is the person's own deletion or a sync race, and a fourth spoken line for that corner is not worth its key). Codex holds the opposite view — reuse the `.notSaved` line when bytes are queued — recorded in §10 for the founder; neither line is true when the person deleted the card themselves, which is the realistic cause. |
| 14 | **`reArmAfterSettle` never re-arms inside a Work session.** | The reply loop's re-arm carries no listen id and re-checks only `sessionActive` after its 300 ms settle; a chat ended during its sign-off and a Work note started at once could in theory be re-armed into. The dismiss animation makes the window unrealistic, but the invariant is cheap to state: a Work note never re-arms. (P3) |

## 4. Changes

All in `Conduck/Conduck/CarPlay/` unless stated. `CarPlayCaptureDestination` (file-scope, internal, `CarPlayRecordingService.swift:108`) is reused for the scene's claim so the two files name a destination the same way.

### P1 — one start at a time (`CarPlaySceneDelegate.swift`)

The claim is a serial bound to the live service, held from a row tap until the service's `begin…` has run or the start was refused, and released only by the holder of that serial.

- State: `private var startClaimSerial: UInt64 = 0`; `private var pendingStart: (serial: UInt64, destination: CarPlayCaptureDestination)?`; `private var lastStartDestination: CarPlayCaptureDestination = .chat` (P2-B reads it).
- `private func claimStart(_ destination: CarPlayCaptureDestination, service: CarPlayRecordingService) -> UInt64?` — `guard service === recordingService, case .idle = service.state, !service.sessionActive, pendingStart == nil else { return nil }`; then `startClaimSerial &+= 1; pendingStart = (startClaimSerial, destination); lastStartDestination = destination; oneShotStartFailureHint = false; return startClaimSerial`.
- `private func startIsLive(_ serial: UInt64, service: CarPlayRecordingService) -> Bool` — `pendingStart?.serial == serial && service === recordingService && interfaceController != nil && service.isSceneActive && service.state == .idle && !service.sessionActive`. Asked after every suspension *group* in `startSession` that precedes a side effect — after `effectiveCarPlayRef`, after the existing-chat branch's two back-to-back awaits (`fetchConversation`, `remoteAgentSnapshot`), after `newChatPickerSnapshot` — i.e. three sites, each the first statement after its await(s), and inside both present completions immediately before `begin…`. A false answer releases the serial and returns; inside a completion it also calls `ensureVoiceDismissed(animated: true)`, because a modal is up with no session behind it (this is also what closes Codex r2 finding 2: a permission revoked or a disconnect during the pre-flight can no longer leave a Listening screen over nothing).
- `private func releaseStart(_ serial: UInt64)` — `if pendingStart?.serial == serial { pendingStart = nil }`. A stale completion from a previous connection can never clear the new connection's claim.
- `startSession`: replaces its opening guard with `guard let serial = claimStart(.chat, service: service) else { return }`. Inside the `Task { @MainActor in … }`: first statement `var handedToPresent = false; defer { if !handedToPresent { self.releaseStart(serial) } }` — every existing early `return` (token missing, `.chooseInstead`, `.setUpOnPhone`) releases through it untouched. Before `ensureVoicePresented`: `guard self.startIsLive(serial, service: service) else { return }` then `handedToPresent = true`. Completion: `{ [weak self, weak service] presented in guard let self, let service else { return }; guard presented, self.startIsLive(serial, service: service) else { self.releaseStart(serial); self.ensureVoiceDismissed(animated: true); return }; service.beginSession(conversationID: conversationID, defaultRef: sessionRef); self.releaseStart(serial) }`.
- `startWorkNote`: `guard let serial = claimStart(.work, service: service) else { return }`; `service.voiceControlTemplate.trailingNavigationBarButtons = []` (P2-A); `ensureVoicePresented(…) { presented in … same shape … service.beginWorkNote(); self.releaseStart(serial) }`.
- `ensureVoicePresented`: completion type becomes `(@MainActor (Bool) -> Void)?` — `true` when the template is presented (already up, or the present succeeded), `false` when `interfaceController` is nil (add `guard let interfaceController else { isVoicePresented = false; completion?(false); return }`) or the present reported failure (the existing `guard success` branch calls `completion?(false)` after resetting the flag). `applyState` passes no completion and is otherwise untouched.
- `disconnectCleanup`: `pendingStart = nil; lastStartDestination = .chat` (and `didConnect`'s stale-service path now routes through it — see below).
- Refresh gates: `observeConversations`' guard becomes `guard !service.sessionActive, self.pendingStart == nil`; the trailing-pass gate in `refreshPicker`'s `defer` adds `self.pendingStart == nil`; the async half's single gate is specified below ("computes first, gates once, then paints").
- `presentGatewayChooser`: capture `let service = recordingService` at push time; the row handler's `Task` opens with `guard let service, service === self.recordingService, !service.sessionActive, self.pendingStart == nil else { return }`.
- A tiny pure gate makes the rule testable without a scene: `enum CarPlayStartGate { static func mayClaim(isIdle: Bool, sessionActive: Bool, claimHeld: Bool) -> Bool; static func isLive(claimSerial: UInt64?, serial: UInt64, serviceIsCurrent: Bool, controllerAttached: Bool, isIdle: Bool, sessionActive: Bool) -> Bool }` in `CarPlaySceneDelegate.swift` (file scope, no `#if` needed beyond the file's), called by `claimStart` / `startIsLive`.
- **Backgrounding and permission invalidate a claim synchronously.** `sceneWillResignActive` sets `pendingStart = nil` beside its existing `isVoicePresented = false` (a start suspended in pre-flight must not begin over Maps or after `sceneDidBecomeActive`'s reconciliation), and `startIsLive` also requires `service.isSceneActive` (make that property `private(set) var` readable from the scene; it is already stored on the service). `.permissionBlocked` is refused by the `.idle` test.
- **Stale completions from a previous connection mutate nothing.** `ensureVoicePresented` and `ensureVoiceDismissed` each capture `let controller = interfaceController` and, inside their completions, `guard self.interfaceController === controller else { completion?(false); return }` before touching `isVoicePresented`, calling `deactivateAudioSession()` or running the caller's completion — a present or dismiss that belonged to a torn-down connection neither flips the new connection's flag nor frees the new service's audio. The starters' failure arm dismisses only when `service === self.recordingService`. The nil-controller refusal sits *before* the `isVoicePresented` fast path.
- **`didConnect` with a stale service calls `disconnectCleanup()`** in place of the ad-hoc `stale.teardown(); recordingService = nil` — the same teardown plus every per-connection reset (`pendingStart`, the refresh latch, the override, the observer generation), so a hard drop that skipped both disconnect callbacks cannot leave a claim or a latch behind.
- **`refreshPicker`'s async half computes first, gates once, then paints.** Gather `configuredRefs`, `customs`, `current`, `recents`, `allBackends` into locals across the awaits with NO template mutation between them; then one gate — `guard service === self.recordingService, template === self.listTemplate, self.pendingStart == nil, !service.sessionActive else { self.pickerRefreshPending = true; return }` and `if case .permissionBlocked = service.state { return }` (the synchronous prologue already painted that row) — then set `leadingNavigationBarButtons` and call `updateSections` (both branches). A refresh refused for a held claim is *retained*, not dropped: `releaseStart` drains it (`if pickerRefreshPending, recordingService?.sessionActive != true { refreshPicker() }`) so a start that was refused after the present, or that never began, still repaints; a start that began is repainted by the `.idle` refresh at session end. The `defer` that clears the latch runs only when `template === self.listTemplate`, so an old connection's refresh cannot unlatch the new one. The adopt path's immediate switcher repaint is dropped behind the modal and lands at session end — acceptable, the title is not readable under the voice template anyway.

### P2-A — no Mute on a Work note (`CarPlaySceneDelegate.swift`)

- `CarPlayRecordingService`: no change — `toggleMute` is unreachable without the button; `endSession` already resets `isMicMuted`.

### P2-B — the hint names the failed row (`CarPlaySceneDelegate.swift`)

- `refreshPicker`, configured branch: ONE hint construction. `let detail = lastStartDestination == .work ? String(localized: "carplay.hint.captureStartFailed.detail.work", defaultValue: "Tap Add to Work to try again.") : String(localized: "carplay.hint.captureStartFailed.detail", defaultValue: "Tap New voice chat to try again.")`, then the existing `CPListItem(text: String(localized: "carplay.hint.captureStartFailed.title", …), detailText: detail)`. The title key still occurs exactly twice in `refreshPicker` (the existing assertion at `CarPlayWorkNoteTests:488`). No new keys.

### P2-C — day-one order (`CarPlaySceneDelegate.swift`)

- `refreshPicker`, no-gateway branch: `var firstSectionItems: [CPListItem] = [self.makeWorkNoteItem(service: service), item]` (the setup `item` is built first, as today; only the array literal changes), then the hint is inserted at index 0 as today. The trailing `firstSectionItems.append(self.makeWorkNoteItem(service: service))` in that branch is removed, so `makeWorkNoteItem(` still occurs exactly twice in `refreshPicker`.

### P2-D — Work retry entries never expire (`Conduck/Conduck/Services/PendingRetryStore.swift`, shared; integrator owns)

- `PendingRetryMetadata.isExemptFromExpiry` unchanged. `isExpired(at:)` applies a 24 h budget (new named constant beside `transcriptionRetryTTL`) to entries with `resolvedDestination == .work && publicationState == .published`; every other entry keeps the 600 s budget. Doc comment: a published Work capture's words stay retryable for a day, long enough to get home from a drive; a clock still retires the queue copy afterwards because the desk holds the recording.
- Nothing else in the store changes: `holdsWorkImage`, the reservation exemption and the discard flow are untouched. Readers of the chain (`isExemptFromExpiry` → `isExpired(at:)` → `partitioningExpired` → `liveQueueLocked` → `claimNext`, `claim(id:)`, `pendingCount`, `load`, `hasPending`, `pendingErrorCode`, `diagnosticSnapshot`, `cleanupExpired`) need no change; notifications are one-shot, not expiry-driven. `load`/claim can still retire an entry whose audio file is missing.

### P2-E — park the words before the attach (`CarPlayRecordingService.swift`)

- `attachWorkNoteTranscript` opens, in this order: `_ = await PendingRetryGuard.recordPublicationState(capture.guardToken, transcript: transcript, publicationState: .published)` (result deliberately ignored — it is false both for an overtaken claim and for an arm that preserved nothing, and those need opposite answers) → `guard isCurrentListen(attemptID) else { return }` → the existing `guard await PendingRetryGuard.stillOwnsCapture(capture.guardToken) else { … savedWithoutWords … }` (which answers true for `audioPreserved == false`, so a valid desk attach is never refused for want of a queue entry) → `guard isCurrentListen(attemptID) else { return }` → `activateVoiceControlState(saving)` → `attachTranscript`. The `.attached` disarm is unchanged; the three armed exits now leave the words beside the bytes when the parking succeeded (it is best-effort: the store also answers false on a persistence failure), and `ContentView.finishWorkRetry` / the Mac `DictationService` retry already finish a parked Work transcript with no speech hop. No reader treats a parked transcript as words already on the desk (`WorkVoiceCaptureCoordinator.recover` still attaches; a repeat of identical words is idempotent).

### P3 — a Work session never re-arms (`CarPlayRecordingService.swift`)

- `reArmAfterSettle`: after the settle sleep and its `sessionActive` re-check, add `guard sessionDestination == .chat else { return }`. Unmute is the only other caller and a Work note has no Mute (P2-A).

### Declined after review (recorded so nobody re-raises them)

- U-29 "Saving…" flicker: dropping the second `saving` activation leaves the first flicker; deferred to rendered QA (step 69), no change.
- A "later"-flavoured rewrite of "Couldn't save that yet. Open Conduck to retry." — the line asks for nothing now; a new key buys nothing.
- Keeping the CAF when `arm` did not preserve: nothing could ever read it (no queue entry) and `endSession` removes it anyway; the honest spoken line for that corner already ships. §1 states the real guarantee instead.
- A deterministic in-suite race test for P1: `CarPlaySceneDelegate`'s starters are private and need a `CPInterfaceController`; the rule is extracted into `CarPlayStartGate` so the decision is unit-tested and the wiring is source-guarded (§6). The founder's QA step 78a exercises the real thing.
